Documentazione Ufficiale API Ecommerce

Guida completa a tutte le chiamate disponibili nel backend Node.js / Express, inclusi parametri URL, query string, JSON body di richiesta, autorizzazioni e risposte previste.

Localhost: http://localhost:3000/api
Remote: http://internopuro.alwaysdata.net/api
Auth Header: Authorization: Bearer <JWT_TOKEN>

🔐 Autenticazione

Generazione del token JWT necessario per autenticare le richieste protette.

POST /api/auth/login
Pubblica

Effettua il login verificando username e password hashata su database. Restituisce il token JWT (valido 8 ore).

Body JSON Richiesto (Content-Type: application/json)
CampoTipoDescrizione
username * string Nome utente dell'account (es. jacopocorbani)
password * string Password in chiaro che verrà confrontata con il bcrypt hash
Esempio Body Richiesta 
{
  "username": "jacopocorbani",
  "password": "password123"
}
Risposta 200 OK 
{
  "message": "Login effettuato con successo",
  "token": "eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9...",
  "user": {
    "id": 1,
    "username": "jacopocorbani"
  }
}

POST /api/user/carts
Token Richiesto

Aggiunge un prodotto al carrello (o somma la quantità se l'articolo è già presente). Crea automaticamente il carrello se non esiste.

Body JSON Richiesto
CampoTipoDescrizione
productID *numberID del prodotto da inserire
quantity *numberQuantità desiderata (deve essere >= 1)
Esempio Body
{
  "productID": 10,
  "quantity": 2
}
DELETE /api/user/carts/:productID
Token Richiesto

Rimuove un prodotto dal carrello dell'utente, oppure ne riduce solo la quantità. Se il prodotto rimosso completamente è un prodotto principale, vengono eliminati automaticamente anche tutti i suoi accessori presenti nel carrello; se invece è un accessorio, viene rimosso solo quello.

Path Parameters
ParametroTipoDescrizione
productID *numberID del prodotto (o accessorio) da rimuovere dal carrello
Body JSON (Opzionale)
CampoTipoDescrizione
quantity opzionalenumberQuantità da togliere (>= 1). Se omessa, o se è maggiore/uguale alla quantità presente, il prodotto viene rimosso interamente dal carrello
Comportamento: il "padre" di un prodotto è determinato dal campo products.productID: se è NULL il prodotto è principale (la rimozione completa elimina anche i suoi accessori dal carrello), altrimenti è un accessorio (viene rimosso solo quello). Se quantity è inferiore alla quantità attuale nel carrello, viene semplicemente scalata senza toccare altre righe (accessori inclusi).
Esempio Body (rimozione parziale)
{
  "quantity": 1
}
Risposta 200 OK (rimozione parziale)
{
  "message": "Quantità del prodotto aggiornata nel carrello"
}
Risposta 200 OK (rimozione completa)
{
  "message": "Prodotto rimosso dal carrello"
}

👑 Admin & Owner (/api/adm)

Richiedono token con ruolo ADMIN (1) oppure OWNER (0). Le query si adattano automaticamente fornendo visibilità estesa all'Owner.

GET /api/adm/users
Admin Owner

Restituisce l'elenco degli utenti con il rispettivo ruolo e il numero totale di ordini effettuati.

Comportamento Ruoli:
• OWNER: Visualizza tutti gli account nel database (inclusi admin e se stesso).
• ADMIN: Visualizza solo gli utenti normali e disabilitati (WHERE roles.ID IN (2, 3)).
Risposta 200 OK
[
  {
    "ID": 2,
    "name": "Mario",
    "surname": "Rossi",
    "role": "USER",
    "n_orders": 3
  }
]
GET /api/adm/users/:userID
Admin Owner

Restituisce i dati anagrafici e tutti gli indirizzi di uno specifico utente.

• ADMIN: Può accedere solo a utenti con ruolo 2 o 3.
• OWNER: Accesso illimitato a qualsiasi ID utente.
Risposta 200 OK
{
  "name": "Mario",
  "surname": "Rossi",
  "role": "USER",
  "addresses": [
    {
      "street": "Via Roma 10",
      "locality": "Centro",
      "zip_code": 43121,
      "city": "Parma",
      "province": "PR",
      "state": "Italia"
    }
  ]
}
PUT /api/adm/users/:userID
Admin Owner

Modifica i dati anagrafici e il ruolo di un utente.

• OWNER: Può assegnare qualsiasi ruolo (incluso Admin o Owner).
• ADMIN: Non può assegnare ruoli privilegiati (0 o 1).
Path Parameters
ParametroTipoDescrizione
userID *numberID dell'utente da aggiornare
Body JSON Richiesto
CampoTipoDescrizione
name *stringNome
surname *stringCognome
roleID opzionalenumberID del nuovo ruolo (0: Owner, 1: Admin, 2: User, 3: Deleted)
Esempio Body
{
  "name": "Mario",
  "surname": "Rossi",
  "roleID": 2
}
DELETE /api/adm/users/:userID
Admin Owner

Disabilita un utente impostando il suo roleID = 3 (DELETED).

GET /api/adm/roles
Admin Owner

Restituisce l'elenco dei ruoli.

• OWNER: Vede tutti i ruoli (0: OWNER, 1: ADMIN, 2: USER, 3: DELETED).
• ADMIN: Vede unicamente i ruoli assegnabili 2 (USER) e 3 (DELETED).
Nota: a differenza della maggior parte delle altre chiamate, l'array è avvolto in un campo results.
Risposta 200 OK
{
  "results": [
    { "ID": 2, "role": "USER" },
    { "ID": 3, "role": "DELETED" }
  ]
}

POST /api/adm/upload
Admin Owner

Carica una o più immagini sul server e restituisce i nomi file da usare come image_path nelle chiamate POST/PUT di prodotti e categorie.

Body (multipart/form-data)
CampoTipoDescrizione
images *file[]Uno o più file immagine, max 5 per richiesta (5MB ciascuno). Tipi non immagine vengono rifiutati
Configurazione server: i file vengono salvati nella cartella indicata dalla variabile d'ambiente UPLOAD_DIR (es. /www/img/prods, la stessa cartella già servita come immagini statiche) e l'URL restituito usa IMAGE_BASE_URL come prefisso. Senza queste variabili, in locale i file finiscono in ./uploads e sono serviti da Express su /uploads.
Risposta 201 Created
{
  "message": "Immagini caricate con successo",
  "images": [
    {
      "filename": "1792069564181-951567895.png",
      "url": "https://internopuro.alwaysdata.net/img/prods/1792069564181-951567895.png"

  ]
}
POST /api/adm/products
Admin Owner

Crea un nuovo prodotto nel catalogo. Supporta due modalità per le immagini: caricarle direttamente nella stessa richiesta (anche più di una), oppure riferire un file già caricato in precedenza.

Modalità 1 — multipart/form-data (consigliata): invia i campi come form-data con uno o più file nel campo images (max 5). Il server li salva e li collega automaticamente al prodotto appena creato.

Modalità 2 — application/json: passa image_path con il nome di un file già caricato in precedenza (es. tramite POST /adm/upload) — una sola immagine.
Body (multipart/form-data oppure application/json)
CampoTipoDescrizione
name *stringNome del prodotto
price *numberPrezzo (es. 49.90)
description opzionalestringDescrizione dettagliata
categoryID opzionalenumberID della categoria di appartenenza
images opzionalefile[]Solo modalità multipart: una o più immagini da caricare (max 5)
image_path opzionalestringSolo modalità JSON: nome di un file immagine già caricato
Risposta 201 Created (con immagini)
{
  "message": "Prodotto creato con successo",
  "productID": 42,
  "images": [
    "https://internopuro.alwaysdata.net/img/prods/1792069568190-565196933.png",
    "https://internopuro.alwaysdata.net/img/prods/1792069568190-278138424.png"
  ]
}
PUT /api/adm/products/:productID
Admin Owner

Modifica i dati del prodotto. Supporta due modalità per aggiungere immagini, più un meccanismo indipendente per rimuoverle dalla galleria.

Modalità 1 — multipart/form-data: uno o più file nel campo images (max 5) vengono caricati e aggiunti alle immagini già collegate al prodotto (non le sostituiscono).

Modalità 2 — application/json: image_path sostituisce l'immagine esistente se ce n'è già una, altrimenti ne inserisce una nuova — comportamento storico, pensato per un prodotto con una sola immagine.

Rimozione immagini: deleteImageIDs (array di ID di products_images) elimina dalla galleria le immagini corrispondenti — funziona in entrambe le modalità ed è indipendente dall'aggiunta di nuove immagini (possono essere usati nella stessa richiesta). Gli ID che non appartengono a questo prodotto vengono ignorati silenziosamente; la risposta riporta solo quelli effettivamente rimossi.
Path Parameters
ParametroTipoDescrizione
productID *numberID del prodotto da aggiornare
Body (multipart/form-data oppure application/json)
CampoTipoDescrizione
name *stringNome del prodotto
price *numberPrezzo aggiornato
description opzionalestringDescrizione
categoryID opzionalenumberID della categoria
images opzionalefile[]Solo modalità multipart: una o più immagini da aggiungere (max 5)
image_path opzionalestringSolo modalità JSON: nome file immagine, sostituisce quella esistente (es. tavolo_lux.jpg)
deleteImageIDs opzionalenumber[]ID (products_images.ID) delle immagini da rimuovere dalla galleria del prodotto
Esempio Body (modalità JSON, sostituzione immagine)
{
  "name": "Tavolo Legno Lux",
  "price": 349.99,
  "description": "Descrizione aggiornata",
  "categoryID": 1,
  "image_path": "tavolo_lux.jpg"
}
Esempio Body (rimozione immagini dalla galleria)
{
  "name": "Tavolo Legno Lux",
  "price": 349.99,
  "deleteImageIDs": [86, 87]
}
Risposta 200 OK (con rimozione immagini)
{
  "message": "Prodotto aggiornato con successo",
  "deletedImageIDs": [86, 87]
}
DELETE /api/adm/products/:productID
Admin Owner

Disattiva un prodotto dal catalogo (active = 0).

POST /api/adm/categories
Admin Owner

Crea una nuova categoria merceologica con eventuale immagine associata (una sola immagine per categoria).

Modalità 1 — multipart/form-data: invia i campi come form-data con il file nel campo image.

Modalità 2 — application/json: passa image_path con il nome di un file già presente nella cartella delle immagini categoria.

Cartella dedicata: a differenza dei prodotti, le immagini delle categorie vengono salvate in una cartella separata, configurata con le variabili d'ambiente CATEGORY_UPLOAD_DIR (es. /www/img/cats) e CATEGORY_IMAGE_BASE_URL (es. https://internopuro.alwaysdata.net/img/cats). POST /adm/upload salva invece nella cartella dei prodotti e non va usato per le categorie.
Body (multipart/form-data oppure application/json)
CampoTipoDescrizione
category *stringNome della categoria (es. Sedie)
image opzionalefileSolo modalità multipart: immagine della categoria (max 5MB)
image_path opzionalestringSolo modalità JSON: nome di un file immagine già caricato
Risposta 201 Created (con immagine)
{
  "message": "Categoria creata con successo",
  "categoryID": 17,
  "image": "https://internopuro.alwaysdata.net/img/cats/1792069967457-235906888.png"
}
